# Spec Delta: context-compaction

## Purpose

定义 AgentCanvas 统一的上下文压缩行为规范：单一压缩算法在轮间、轮内、手动三个触发点产生一致结果，压缩输入覆盖完整历史（含工具条目），压缩产物（摘要与逐字保留）与快照持久化的可观察行为。

## ADDED Requirements

### Requirement: 单一压缩算法多触发点一致

系统 SHALL 使用同一个压缩算法处理轮间（新消息到达前）、轮内（工具循环进行中）与手动三种触发；对相同的输入历史，三种触发 MUST 产生结构一致的输出（相同的保留规则、摘要角色与包装）。触发点之间的差异 MUST 仅限于持久化外壳（写回的快照行类型），不得存在第二套总结/保留逻辑。

#### Scenario: 轮间与轮内对同一历史产生同构输出

- **WHEN** 轮间触发与轮内触发分别处理内容相同的消息历史（mock 总结器返回同一段摘要文本）
- **THEN** 两者输出的保留消息集合逐条相同（角色、内容、顺序），且摘要消息均为 user 角色、均以同一固定前缀开头

#### Scenario: 手动触发强制压缩

- **WHEN** 用户发起手动压缩且当前上下文未达到阈值
- **THEN** 系统仍执行压缩（强制模式），产生新的快照版本，且不进入模型对话循环

### Requirement: 压缩触发阈值

系统 SHALL 在已测量上下文达到窗口 tokens 的 90% 时触发压缩；硬上限 SHALL 为窗口减去预留输出与安全边际；单条用户输入超过硬上限时 MUST 报溢出错误而不是静默截断。

#### Scenario: 达到阈值触发

- **WHEN** 渲染后的上下文为 116,000 tokens、窗口为 128,000（阈值 115,200）
- **THEN** 触发压缩，压缩后上下文低于硬上限

#### Scenario: 未达阈值不触发

- **WHEN** 渲染后的上下文为 80,000 tokens、窗口为 128,000 且非强制模式
- **THEN** 不产生新快照，不调用总结器（总结器调用次数为 0）

#### Scenario: 单条输入超硬上限

- **WHEN** 最新一条用户消息单独超过硬上限
- **THEN** 返回溢出错误，错误信息包含估计与允许的 token 数

### Requirement: 压缩输入覆盖工具条目

压缩器接收的历史 MUST 包含 text、function_call、function_call_output 三类条目；若存在上一份摘要（滚动压缩），该摘要 MUST 作为输入参与本次总结。单条超过长度上限的 tool output MUST 在送入总结器前被截断。标记为可忽略的消息（系统回声）MUST 被排除出总结输入。

#### Scenario: 工具条目进入总结输入

- **WHEN** 历史包含 2 条 text、3 条 function_call、3 条 function_call_output，触发压缩（mock 总结器记录收到的消息）
- **THEN** 总结器收到的输入包含全部 8 条内容（含工具调用的参数与结果文本），且收到 1 次调用

#### Scenario: 滚动压缩携带旧摘要

- **WHEN** 会话已有版本 1 快照（摘要 S1），再次触发压缩
- **THEN** 总结器输入包含 S1 的内容，新快照的 parent 指向版本 1 快照、版本号为 2

#### Scenario: 超长 tool output 被截断

- **WHEN** 某条 function_call_output 内容超过单条送总结上限
- **THEN** 总结器收到的该条内容为截断后的文本（长度不超过上限），其余条目不受影响

#### Scenario: 系统回声被排除

- **WHEN** 历史包含 content_type 为系统回声的消息（如 "/compact" 与 "Context compacted."）
- **THEN** 总结器输入不包含这两条消息的内容

### Requirement: 逐字保留规则

压缩后 MUST 从尾部向前保留 user 角色消息，总预算 20,000 tokens；预算耗尽时遇到的第一条消息 MUST 被截断后保留（不丢弃）；以摘要前缀开头的消息 MUST 不计入保留集合。快照的 First/LastMessageID MUST 锚定保留下来的 user 消息区间。

#### Scenario: 预算内全量保留

- **WHEN** 尾部起 5 条 user 消息共 9,000 tokens，触发压缩
- **THEN** 5 条全部逐字保留，快照 First/LastMessageID 分别为这 5 条的首条与末条 ID

#### Scenario: 超预算消息截断保留

- **WHEN** 尾部起第 3 条 user 消息单独即超过剩余预算
- **THEN** 该条被截断到剩余预算后保留，更早的 user 消息不再保留（保留过程终止）

#### Scenario: 摘要消息不占保留预算

- **WHEN** 历史中存在一条以摘要前缀开头的 user 消息
- **THEN** 该条不出现在保留集合中，不消耗 20,000 tokens 预算

### Requirement: 摘要注入形态

压缩产生的摘要 MUST 以 user 角色消息注入后续上下文，内容 MUST 以固定前缀 `SUMMARY:` 开头；总结器返回空内容时 MUST 以固定兜底文本代替。

#### Scenario: 摘要进入下一轮上下文

- **WHEN** 压缩完成后发起新一轮对话
- **THEN** 请求消息序列中存在一条 user 角色、以 `SUMMARY:` 前缀开头的消息，其内容为快照摘要正文

#### Scenario: 空摘要兜底

- **WHEN** 总结器返回空白内容（mock 返回空字符串）
- **THEN** 快照摘要为固定兜底文本，且该兜底文本出现在下一轮上下文中

### Requirement: 总结调用自身超限的重试

当总结调用因上下文超限失败时，系统 MUST 从最早条目开始逐条移除并重试；只剩一条仍失败时 MUST 返回压缩失败错误而不是无限循环。

#### Scenario: 丢最早条目重试成功

- **WHEN** 总结调用第一次返回上下文超限错误、丢弃最早一条后第二次成功（mock 按调用次序返回错误/摘要）
- **THEN** 总结器共被调用 2 次，最终快照摘要为第二次返回的内容，第二次输入不含最早那条消息

#### Scenario: 只剩一条仍超限

- **WHEN** 历史缩减到 1 条时总结调用仍返回上下文超限错误
- **THEN** 返回压缩失败错误，不产生新快照，不继续重试

### Requirement: 快照持久化与并发互斥

每次压缩成功 MUST 持久化一行快照记录，包含摘要正文、前后 token 数、版本链（parent + version 递增）；同一会话并发压缩 MUST 通过互斥声明避免产生分叉版本；相同输入重复压缩 MUST 通过指纹去重不产生重复行。

#### Scenario: 并发压缩只产生一个胜出版本

- **WHEN** 两个执行体同时对同一会话发起压缩（一个持有互斥声明，另一个未持有）
- **THEN** 未持有者重新加载已产生快照并复用，最终该会话同一版本链上不出现两条相同版本号的 completed 快照

#### Scenario: 相同输入指纹去重

- **WHEN** 以完全相同的消息集合与参数两次创建快照行
- **THEN** 数据库中该会话对应指纹仅存一行（第二次写入为无操作）

### Requirement: token-budget 旁路模式保留

系统 SHALL 保留可配置的 token-budget 压缩模式：该模式下不调用总结器，仅按角色保留消息；统一算法核心 MUST 不包含该旁路逻辑，旁路以独立分支存在。

#### Scenario: token-budget 模式不调用总结器

- **WHEN** 配置为 token-budget 模式且触发压缩（mock 总结器可被计数）
- **THEN** 总结器调用次数为 0，输出仅含按角色保留的消息，快照行状态为 completed
